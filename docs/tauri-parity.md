# Tauri desktop parity checklist

**The GPUI build at `d74874059c18` has 28 open parity findings.** Six warrant an immediate release hold. A stale diff can still offer a destructive file action, upgrades reset preferences, the updater loses its link to the verified bytes, ordinary controls lose keyboard and screen-reader access, and the bundle raises the minimum macOS version for Intel users. Each finding below has a check for restoring parity.

The shipped baseline is `app-v0.4.1` (`3d3b2f3ab085`). I also compared the last Tauri implementation, `5c8dfb9e8655`, immediately before the GPUI-only commit. Between those two Tauri revisions the frontend changed theme styling and scrolling. Item 23 identifies the scrolling change specific to the later revision. The scope covers the macOS app, previously saved data, the bundled CLI, and the tooling used to demonstrate parity.

## Deliberate differences that affect existing workflows

These deserve an explicit product decision if the release promises identical behavior.

- **Pinned and range comparisons.** Tauri offered current-change file mutations and the merge-tool shortcut inside a fresh comparison. GPUI makes any comparison with an explicit base read-only. Someone reviewing that comparison must return to the parent diff to act. Preserve a clear route to act on the intended change with fresh coordinates. [Menu restriction](../crates/jiji-desktop/src/views/workbench/mod.rs#L728) · [merge-tool restriction](../crates/jiji-desktop/src/views/workbench/diffpane.rs#L433)
- **Title bar and tabs.** Tauri had a one-click history-search button, a separate theme menu, a registered-license button and a visible close button on the active tab. GPUI's command field opens the palette, history search remains on ⌘⇧F, appearance and registered-license controls live in Settings, and tab close appears on hover. Its fullscreen menu item also keeps the label “Enter Full Screen” while fullscreen. [Title bar and tabs](../crates/jiji-desktop/src/shell/topbar.rs#L116) · [native menu](../crates/jiji-desktop/src/shell/mod.rs#L187)
- **Status bar.** Tauri showed the newest operation, including an automatic working-copy snapshot, and named the backend. GPUI deliberately skips snapshot operations in the idle status line and shows the backend indicator for mock data. Operations history remains available. [Status bar](../crates/jiji-desktop/src/shell/statusbar.rs#L141)
- **Visual cues.** The graph changed working-copy and ordinary node symbols, lane widths and colors, selection styling, and overflow refs. Change-header metadata can clip in narrow panes. Bookmark rows reserve space for actions, the main diff's horizontal thumb appears on hover, and panel and layout transitions were removed. Use the same repository, theme and window widths to review the cues that convey state. [Graph](../crates/jiji-desktop/src/views/workbench/graph.rs) · [change header](../crates/jiji-desktop/src/views/workbench/header/bars.rs) · [diff surface](../crates/jiji-desktop/src/diff/view.rs)

## Tooling lost in the cutover

- **Repeatable offline GUI fixtures.** The Tauri `scripts/visual-harness` could replay captured repos and diffs, seeded GitHub PRs and landing plans, and selected UI errors and states. A separate `dump_diff` example printed refined diff lines and changed spans for a given real change and optional path. GPUI has headless screenshots, scripted input, a mock repo and shared forge test data. Its ordinary desktop tests deliberately suppress GitHub credentials, and there is no equivalent captured-forge UI replay. Port the outcomes that exercised stack selection, plan options, late responses, CI and auto-land. [GPUI scripted testing](../crates/jiji-desktop/README.md) · [test token behavior](../crates/jiji-desktop/src/host/forge.rs#L66)
- **Local release preflight.** Tauri's `scripts/release-preflight` checked the public feed, repo visibility, required signing-secret names and an available local signing identity, among other checks. The new workflow signs, notarizes and builds the universal DMG and updater feed. The local preflight command and its early feedback are gone. [Release procedure](../RELEASING.md) · [release workflow](../.github/workflows/release-macos.yml)
- **Source compatibility for contributors.** Removing the web frontend also removed `bun run bindings`, the generated TypeScript DTOs and the `ts-rs` implementations on shared Rust types. The public `jiji_forge::reconcile::TextPlan::has_write()` helper was removed. It had no in-tree callers. The Windows-specific terminal fallback in Tauri also disappeared, and the current desktop launcher imports Unix file permissions unconditionally. These affect code consumers or experimental source builds. The release matrix was macOS-only. [Snapshot types](../crates/jiji-core/src/snapshot.rs) · [forge text plan](../crates/jiji-forge/src/reconcile.rs#L180) · [desktop launcher](../crates/jiji-desktop/src/host/cli.rs#L153)

## Verification performed

- The archived Tauri frontend passed **409 tests in 39 files**. The current workspace passed **444 Rust tests**, including **127 desktop tests**. The filesystem-watcher test timed out once in a sandboxed run, then passed alone and in the full rerun with normal macOS filesystem notifications. Its source is identical to 0.4.1. [Watcher test](../crates/jiji-core/src/watch.rs#L343)
- Eight additional checks in a temporary copy of the GPUI source reproduced stale-diff mutation eligibility, all-or-nothing saved-view loading, missing image-format mappings, prerelease update ordering, the Greek diff-find mismatch, unavailable Edit menu actions on a focused diff, differences in Rust and non-ASCII syntax highlighting, and a failed Publish Retry with an unchanged successful PR response. They used synthetic data, in-memory windows and a stubbed forge.
- Compared the installed Tauri 0.4.1 binary with the locally built GPUI binary. All **23** top-level and subcommand help screens match byte for byte. The `jiji-cli` source and tests also have an empty diff from the release tag.
